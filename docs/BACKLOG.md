# BACKLOG — идеи из анализа проекта, в работу пока не берутся

Здесь лежат пункты, которые не вошли в текущую итерацию. Порядок примерно по
убыванию ценности. Перед взятием в работу — обсудить и, если нужно, внести в
`docs/SPEC.md` явным решением владельца.

## Поведение

1. **`--udp-listener` без root на обычном сервере.** Каталоги `/etc/wireguard` и
   `/etc/amnezia/amneziawg` обычно принадлежат root и имеют права `0700`, поэтому
   проверка портов по конфигам (6.14) падает с кодом `1` (`permission denied`), хотя
   SPEC 2.4 разрешает listener без root для непривилегированных портов. Решить в
   SPEC: пропускать недоступные каталоги (порты поднятых интерфейсов и так видны в
   `/proc/net/udp`) или требовать root, если конфиги нельзя прочитать (код `6`).
2. **Поддержка других видов туннелей.** Добавить IP-IP и GRE наряду с
   WireGuard/AmneziaWG.

## Противоречия и пробелы в SPEC

1. **Матрица 4.3, строка `--mimic`.** Значение «н» стоит в колонке `down`, а в
   колонке `add-client` — «—». Это противоречит 4.4 и 6.12; код и тесты
   (`internal/cli/cli_test.go`) следуют 6.12. Исправить таблицу.
2. **Конфиг не помещается в QR (6.5).** Клиент к этому моменту уже записан, а krot
   завершается с кодом `3`; при повторном запуске из автоматизации krot вернёт код
   `5`. Блок `--keenetic` в этом случае не выводится. Помещается ли конфиг в QR,
   можно проверить до записи (текст известен заранее); также нужно определить
   порядок вывода при ошибке.

## Тесты и CI

1. **Двойной CI на тегах.** `ci.yml` запускается `on: push` без фильтра веток,
   поэтому на тег `v*` CI идёт дважды: сам и через `workflow_call` из
   `release.yml`.
2. **Job `build` в `ci.yml`** собирает бинарь своей командой, а не через
   `scripts/build-release.sh`/Makefile, и не передаёт `main.date` — бинарь
   сообщает «built unknown».
3. **`make check` проверяет меньше, чем CI:** нет `govulncheck` и порога покрытия
   90%; список `fuzz-smoke` задан вручную и не подхватит новые fuzz-targets
   (SPEC 9.1 требует все).
4. **`scripts/smoke.sh`** ищет в changelog пакета строки именно от 0.7.3 и не
   проверяет запись текущей версии.
5. **`scripts/build-release.sh`** запускает `dist/krot-linux-amd64` для генерации
   completion — на arm64-хосте сборка упадёт.

## Мелкие замечания по коду и документации

1. При повторяющемся AWG-ключе в чужом конфиге `renderClient` берёт первое
   значение, а `Interface.Get` — последнее.
2. `UnlockPeer`: строка блока с пробелами перед `#~` (ручная правка) остаётся
   закомментированной, а `# krot:locked` при этом удаляется.
3. Аллокатор не учитывает `AllowedIPs` чужих peer'ов шире одного адреса (`/32`,
   `/128`) и может выдать адрес внутри чужой маршрутизируемой подсети (поведение
   закреплено тестами) — описать это в документации.
4. PSK для `wg set` можно передавать через `/dev/stdin` вместо временного файла
   в `$TMPDIR`.
5. README и man-страницы не описывают поддержку конфигов в виде символических
   ссылок (T49) и формат `--udp-listener --json` (6.14).
